# Секции

Секция — это правило маршрутизации: какой трафик (списки доменов и подсетей) и куда его отправлять. Секции настраиваются в LuCI: **Службы → Okop → Секции**. Их может быть несколько, например одна через VPN для одних сервисов и одна через прокси для других.

Секции показаны таблицей: для каждой видно подключение (протокол и имя сервера или интерфейс, без паролей и ключей) и краткую сводку списков. Кнопка **Изменить** открывает окно с настройками секции на трёх вкладках: **Подключение**, **Списки** и **Дополнительно**. Новая секция добавляется полем под таблицей: имя может содержать латинские буквы, цифры и `_`.

## Тип подключения

| Тип | Что делает |
|---|---|
| **Proxy** | Отправляет трафик через прокси-сервер: VLESS, Shadowsocks, Trojan, SOCKS, Hysteria2 |
| **VPN** | Отправляет трафик в сетевой интерфейс роутера: WireGuard, AmneziaWG, OpenVPN и т. п. |
| **Block** | Блокирует трафик к доменам и подсетям из списков |
| **Exclusion** | Отправляет трафик напрямую, в обход остальных секций |

### Порядок правил

1. **Block**, затем **Exclusion**. Они срабатывают раньше секций Proxy и VPN, поэтому Exclusion удобно использовать, чтобы вывести отдельные домены из большого списка. Например, если секция с `russia_inside` идёт через VPN, а один сайт из этого списка нужен напрямую.
2. Устройства из «Исключённых из маршрутизации IP» (см. [settings.md](settings.md#маршрутизация)) идут напрямую.
3. «Полностью маршрутизируемые IP» каждой секции.
4. Списки секций Proxy и VPN — в том порядке, в котором секции идут в таблице. Если домен есть в списках двух секций, сработает та, что выше. Порядок меняется перетаскиванием строк за значок ☰.

## Proxy

**Тип конфигурации** определяет, как задаётся сервер.

- **Connection URL** — одна ссылка: `vless://`, `ss://`, `trojan://`, `socks4://`, `socks5://`, `hy2://` или `hysteria2://`. Примеры поддерживаемых вариантов (транспорты, Reality, obfuscation) — в [String-example.md](../String-example.md).
- **Selector** — несколько ссылок. По умолчанию используется первая, переключать можно вручную на вкладке **Dashboard**.
- **URLTest** — несколько ссылок, Okop сам выбирает самый быстрый сервер:
  - **URLTest Check Interval** — как часто проверять серверы (по умолчанию каждые 3 минуты);
  - **URLTest Tolerance** — на сколько миллисекунд новый сервер должен быть быстрее текущего, чтобы на него переключиться (50–1000, по умолчанию 50);
  - **URLTest Testing URL** — адрес для проверки (по умолчанию `https://www.gstatic.com/generate_204`).

  Автоматический выбор можно переопределить вручную на вкладке **Dashboard**.
- **Outbound Config** — готовый outbound sing-box в формате JSON. Нужен для того, что не выражается ссылкой.

**UDP over TCP** — передавать UDP внутри TCP-соединения. Работает для SOCKS и Shadowsocks, если сервер это поддерживает.

## VPN

- **Network Interface** — интерфейс туннеля, например `wg0` или `awg0`. Сам туннель настраивается средствами OpenWrt, Okop только направляет в него трафик.
- **Domain Resolver** — резолвить домены этой секции через отдельный DNS-сервер, запросы к которому тоже идут через туннель. Полезно, если сервис отдаёт разные адреса в зависимости от страны.

Если интерфейс туннеля пропал (туннель упал или ещё не поднялся), sing-box продолжит работать: перестанет открываться только трафик этой секции.

## Списки

Списки из разных источников можно сочетать в одной секции.

### Community-списки

Готовые списки доменов из [itdoginfo/allow-domains](https://github.com/itdoginfo/allow-domains), которые поддерживают авторы Podkop. Сервисы:

- **регионы:** `russia_inside`, `russia_outside`, `ukraine_inside`;
- **тематические:** `geoblock`, `block`, `porn`, `news`, `anime`;
- **сервисы:** `youtube`, `discord`, `meta`, `twitter`, `hdrezka`, `tiktok`, `telegram`, `cloudflare`, `google_ai`, `google_play`, `hodca`, `roblox`;
- **сети хостингов (ASN):** `hetzner`, `ovh`, `digitalocean`, `cloudfront`.

Ограничения:

- Одновременно можно выбрать только один региональный список.
- `russia_inside` уже включает большинство сервисов. Вместе с ним можно выбрать только `meta`, `twitter`, `discord`, `telegram`, `cloudflare`, `google_ai`, `google_play`, `hetzner`, `ovh`, `hodca`, `roblox`, `digitalocean`, `cloudfront`. Остальные LuCI уберёт сама.

Для `twitter`, `meta`, `discord`, `telegram`, `cloudflare`, `roblox` и сетей хостингов Okop вдобавок скачивает списки подсетей и перехватывает трафик к ним в nftables. Так до sing-box доходят и соединения, которые открываются по IP в обход DNS. Для Discord дополнительно перехватываются UDP-порты 19000–20000 и 50000–65535, через которые идут голосовые звонки.

### Пользовательские домены и подсети

**User Domain List Type** и **User Subnet List Type** задают, как вводить список:

- **Dynamic List** — по одной записи в поле;
- **Text List** — одним текстом через запятую, пробел или перевод строки. Комментарии пишутся после `//`.

Домен охватывает все поддомены: `example.com` означает и `www.example.com`, и `api.example.com`. Регистр не важен, путь после домена отбрасывается: `Example.com/page` — это `example.com`. Подсети задаются в формате CIDR (`103.21.244.0/22`) или отдельными IP. Неправильные записи пропускаются.

### Локальные списки

Путь к файлу на роутере, например `/root/lists/my.lst`. Формат — текстовый, одна запись на строку (запятые и пробелы тоже разделяют записи), комментарии — после `#` или `//`. Кроме того, в файле можно указать ссылку целиком (от `https://example.com/page` останется `example.com`), а запись с точкой в начале (`.example.com` или `*.example.com`) означает только поддомены. Файл читается при каждом старте Okop.

### Удалённые списки

URL списка доменов или подсетей.

- **`.srs`** (бинарный rule-set sing-box) и **`.json`** (исходный rule-set) скачиваются в постоянное хранилище и переживают перезагрузку, как и community-списки. Подробнее — в [how-it-works.md](how-it-works.md#списки).
- **Любой другой URL** считается текстовым списком (одна запись на строку). Он тоже сохраняется на флеше и применяется при старте из сохранённой копии.

## Дополнительно

- **Fully Routed IPs** — IP или подсети устройств в LAN, весь трафик которых идёт через эту секцию независимо от списков. Например, телевизор целиком через VPN.
- **Enable Mixed Proxy** и **Mixed Proxy Port** — поднять на LAN-адресе роутера HTTP/SOCKS5-прокси на указанном порту. Всё, что приходит в этот прокси, идёт через секцию. Удобно для отдельных программ или для проверки секции.
- **Resolve real IP for routing** — для трафика этой секции sing-box сначала резолвит домен в настоящий IP (правило `resolve`) и только потом отправляет соединение. По умолчанию выключено.
