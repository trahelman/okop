# DNS

Маршрутизация по доменам работает только через DNS роутера: именно в нём домену из списка выдаётся fake-IP (см. [how-it-works.md](how-it-works.md)).

## DNS на устройствах

Устройство должно получать DNS от роутера. Проверка на устройстве:

```
nslookup fakeip.podkop.fyi
```

Ответ должен быть из диапазона `198.18.0.0/15`, например `198.18.0.3`. Если пришёл другой адрес, устройство или браузер пользуется сторонним DNS.

Что обычно мешает:

- **Защищённый DNS (DoH) в браузере.** Он включён по умолчанию во многих браузерах.
  - Chrome: *Настройки → Конфиденциальность и безопасность → Использовать безопасный DNS* — выключить.
  - Firefox: *Настройки → Приватность и защита → DNS через HTTPS* — выключить.
- **Частный DNS на Android:** *Настройки → Сеть → Частный DNS* — выключить или «Автоматически».
- **DNS, прописанный вручную** в настройках сетевого адаптера. Нужно получение DNS автоматически, по DHCP. На Windows, если `nslookup` отдаёт IPv6-адреса, отключите IPv6 на адаптере.
- **Устройства с зашитым DNS** (некоторые телевизоры, Chromecast) ходят напрямую на `8.8.8.8`. Их запросы на порт 53 можно перенаправить на роутер правилом firewall:
  ```
  config redirect
      option name 'Intercept-DNS'
      option src 'lan'
      option proto 'tcp udp'
      option src_dport '53'
      option dest_port '53'
      option target 'DNAT'
  ```
  Добавьте в `/etc/config/firewall` и выполните `service firewall restart`. DNS over TLS (порт 853) так не перехватить, его можно только заблокировать.

## Какой DNS-сервер выбрать

DNS-сервер из настроек резолвит все домены, которых нет в списках. Домены из списков получают fake-IP, а их настоящий адрес определяет уже прокси-сервер или DNS-резолвер секции.

- Зарубежные DoH и DoT могут работать нестабильно, если их блокируют. Надёжнее всего обычный UDP-DNS провайдера или Яндекса (`77.88.8.8`, `77.88.8.1`).
- Для секций VPN включайте **Domain Resolver** ([sections.md](sections.md#vpn)): тогда домены этой секции резолвятся через туннель, и шифровать DNS отдельно не нужно.

## AdGuard Home

**AdGuard Home как DNS-сервер для Okop.** AdGuard Home на роутере должен слушать отдельный адрес, например `127.0.0.10`. Нельзя использовать `127.0.0.42` (его слушает sing-box) и `127.0.0.53`. В `/etc/adguardhome.yaml`:

```yaml
dns:
  bind_hosts:
    - 127.0.0.10
  port: 53
```

Выполните `service adguardhome restart`. В настройках Okop укажите тип DNS `UDP` и сервер `127.0.0.10`. Если AdGuard Home стоит на другом устройстве, укажите его адрес.

**AdGuard Home перед Okop.** DHCP раздаёт устройствам адрес AdGuard Home, а upstream-сервером в нём указан роутер. Так в статистике AdGuard Home видны отдельные устройства.

## Ручная настройка dnsmasq

Если включено **Не трогать мой DHCP!** (`dont_touch_dhcp`), Okop не меняет dnsmasq. Направить DNS в sing-box нужно вручную, в секции dnsmasq в `/etc/config/dhcp`:

```
option noresolv '1'
option cachesize '0'
list server '/corp.lan/10.0.0.53'
list server '127.0.0.42'
```

Общим upstream-сервером должен быть только `127.0.0.42`. Перенаправления для отдельных доменов, как `/corp.lan/10.0.0.53`, можно оставлять. Учтите, что [защита DNS](how-it-works.md#защита-dns) в этом режиме не работает: если sing-box остановится, DNS в сети пропадёт.

Без этой опции ничего настраивать не нужно: Okop сам переключает dnsmasq и сохраняет перенаправления для отдельных доменов.

## Логи DNS-запросов

Включите **Сеть → DHCP и DNS → Журнал → Журналировать запросы** (опция `logqueries`) и смотрите запросы командой:

```
logread -f -e dnsmasq
```

Для проверки с компьютера в LAN: `nslookup example.com 192.168.1.1` или `dig example.com @192.168.1.1`.
