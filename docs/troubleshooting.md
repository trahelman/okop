# Диагностика и решение проблем

## С чего начать

1. Откройте **Службы → Okop → Диагностика** **с устройства в LAN**. При открытии извне часть проверок покажет ложные ошибки.
2. Нажмите **Запустить диагностику**. Зелёный — проверка пройдена, жёлтый — предупреждение, красный — ошибка.
3. Исправляйте ошибки сверху вниз: нижние проверки часто падают из-за верхних.

После обновления Okop очистите кэш браузера для LuCI, иначе диагностика может работать со старой версией интерфейса.

## Что должно работать

Маршрутизация по доменам работает, когда выполнены все условия:

1. Устройство отправляет DNS-запросы роутеру (см. [dns.md](dns.md)).
2. Роутер — шлюз устройства, по крайней мере для `198.18.0.0/15`.
3. dnsmasq пересылает запросы в `127.0.0.42`.
4. sing-box запущен и слушает `127.0.0.42:53` и `127.0.0.1:1602`.
5. nftables помечает трафик и отправляет его в sing-box.
6. Подключение секции работает, у роутера есть интернет.

## Проверки на устройстве

```
nslookup fakeip.podkop.fyi
```

- **Адрес из `198.18.0.0/15`** — DNS в порядке.
- **Другой адрес** — устройство использует сторонний DNS, см. [dns.md](dns.md#dns-на-устройствах). В выводе `nslookup` смотрите строку `Server`.
- **Нет ответа от роутера** — проблема на роутере, см. ниже.

```
curl -v https://fakeip.podkop.fyi/check
```

- **`"fakeip": true`** — трафик проходит через sing-box.
- **Зависает** — трафик не доходит до sing-box: устройство идёт мимо роутера или не работают правила nftables.

Если в терминале всё работает, а в браузере нет, откройте `https://fakeip.podkop.fyi/check` в самом браузере. Ответ `false` означает, что в браузере включён защищённый DNS.

## Проверки на роутере

Службы и порты:
```
netstat -lnup | grep -E ':53 |:1602 '
netstat -lntp | grep -E ':53 |:1602 '
```
sing-box должен слушать `127.0.0.42:53` и `127.0.0.1:1602`, dnsmasq — `127.0.0.1:53` и LAN-адрес роутера.

Настройки dnsmasq:
```
uci show dhcp.@dnsmasq[0] | grep -E 'server|noresolv|cachesize'
```
Пока Okop работает, должно быть `noresolv='1'`, `cachesize='0'`, а среди `server` — `127.0.0.42` и, возможно, ваши перенаправления вида `/домен/адрес`.

Если Okop запущен, а `127.0.0.42` там нет, значит, сработала [защита DNS](how-it-works.md#защита-dns): sing-box не отвечает или не может резолвить, и dnsmasq временно вернулся на обычные серверы. Интернет в сети при этом работает, но маршрутизация по доменам — нет. Причину ищите в логах:
```
logread -e okop | grep -E 'guard|switching|sing-box is'
logread -e sing-box | tail -50
```

Правила nftables:
```
nft list table inet OkopTable
```
Если таблицы нет, а Okop включён, скорее всего, запуск не удался: sing-box не принял конфиг или в настройках секции или подключения чего-то не хватает. Okop в этом случае убирает перехват и возвращает настройки dnsmasq, то есть сеть работает так, будто он выключен. Причина — в логе:
```
logread -e okop | grep -iE 'fatal|start failed'
```
Счётчики правил с `198.18.0.0/15` в цепочке `mangle` должны расти при открытии сайтов из списков. Если они нулевые, трафик устройств не доходит до роутера — проверьте DNS и шлюз на устройстве. Правила маркировки трафика от других программ (остатки Getdomains, `vpn-client` на прошивках GL.iNet) конфликтуют с Okop, их нужно убрать.

Туннель подключения-интерфейса:
```
curl -v --interface wg0 ifconfig.me
```

Скачанные списки:
```
ls -la /etc/okop/rulesets/
logread -e okop | grep -iE 'rule set|download'
```
Размер пустого списка — несколько байт. Такой список не содержит правил, пока его не удалось скачать.

## Команды

| Команда | Что делает |
|---|---|
| `okop global_check` | Полная проверка системы. Приложите её вывод к сообщению о проблеме |
| `okop check_logs` | Логи Okop с последнего запуска |
| `okop check_sing_box_logs` | Логи sing-box |
| `okop check_dns_available` | Проверка DNS |
| `okop check_nft_rules` | Проверка правил nftables |
| `okop check_fakeip` | Проверка fake-IP на роутере |
| `okop list_update` | Скачать списки прямо сейчас |
| `okop show_config` | Настройки Okop без секретов |
| `okop show_sing_box_config` | Сгенерированный конфиг sing-box |
| `service okop restart` | Перезапуск |

## Частые проблемы

**Работает на одних устройствах и не работает на других.** Почти всегда дело в DNS на этих устройствах, см. [dns.md](dns.md#dns-на-устройствах).

**Сайты из списков не открываются, остальные работают.**
- Проверьте подключение секции на вкладке **Dashboard**: там видна задержка до сервера, а у группы — какой участник сейчас используется. Дашборд проверяет подключения при открытии и раз в минуту, а подключение, которое не ответило, отмечает красным: «Нет связи». Там же строка **Защита DNS** показывает, не отключила ли защита маршрутизацию через sing-box, и с какого времени, см. [how-it-works.md](how-it-works.md#защита-dns).
- Для VPN проверьте туннель командой `curl --interface`.
- Если после перезагрузки списки ещё не скачались, эти сайты временно идут напрямую. Посмотрите `logread -e okop` и попробуйте `okop list_update`.

**Ссылка на прокси работает в другом клиенте, но не в Okop.** Экспортируйте конфиг из NekoBox/Nekoray и вставьте outbound в подключение типа **JSON для sing-box**, см. [connections.md](connections.md#типы).

**Серверы на Xray 26.7.11 и новее не принимают подключения sing-box.** На сервере укажите `minClientVer` `1.8.0` (в 3X-UI: Reality → Min Client Ver).

**Не работает интернет после остановки Okop.** Okop возвращает dnsmasq к исходным настройкам. Если исходно DNS-серверы не были заданы, dnsmasq берёт их у провайдера: проверьте, что у WAN-интерфейса включено «Использовать DNS-серверы, объявленные узлом», или добавьте сервер в **Сеть → DHCP и DNS → Перенаправления**.

**Нестабильный WAN (PPPoE, USB-модем).** Включите [мониторинг интерфейсов](settings.md#интерфейсы) и выполните `service okop restart`.

## Сообщить о проблеме

Создайте issue на [GitHub](https://github.com/trahelman/okop/issues) и приложите:

- снимок вкладки **Диагностика** с проблемного устройства;
- вывод `okop global_check`;
- логи: `okop check_logs` и `okop check_sing_box_logs`.
