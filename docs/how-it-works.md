# Как устроен Okop

Okop — надстройка над [sing-box](https://sing-box.sagernet.org/) для OpenWrt. Он собирает конфигурацию sing-box из настроек в LuCI (`/etc/config/okop`), настраивает nftables и dnsmasq и следит, чтобы всё это работало вместе.

## Путь запроса

```
устройство в LAN
   │ 1. DNS-запрос youtube.com
   ▼
dnsmasq (роутер) ──► sing-box DNS (127.0.0.42)
                        │ 2. домен есть в списках → fake-IP 198.18.x.x
                        │    домена нет в списках → настоящий IP от DNS-сервера из настроек
   │ 3. соединение на 198.18.x.x
   ▼
nftables: адрес из диапазона fake-IP или из списка подсетей → метка → tproxy
   ▼
sing-box (tproxy 127.0.0.1:1602) ──► исходящее подключение секции: прокси, VPN-интерфейс или напрямую
```

1. **DNS.** dnsmasq на роутере пересылает запросы в sing-box. Если домен есть в списках какой-нибудь секции, sing-box отвечает fake-IP из диапазона `198.18.0.0/15` и запоминает, какому домену он выдан. Остальные домены резолвятся обычным образом через DNS-сервер из настроек.
2. **Перехват.** Правила nftables в таблице `OkopTable` помечают трафик от устройств с исходных интерфейсов (по умолчанию `br-lan`), если адрес назначения — fake-IP или подсеть из списков. Помеченный трафик через tproxy попадает в sing-box.
3. **Маршрутизация.** sing-box по fake-IP восстанавливает домен и выбирает исходящее подключение секции, в списки которой он входит. Весь остальной трафик идёт напрямую и sing-box не затрагивает.

Поэтому домены работают только тогда, когда устройство получает DNS от роутера. Если на устройстве прописан свой DNS или включён DNS over HTTPS в браузере, маршрутизация по доменам для него не сработает. Маршрутизация по подсетям при этом работает.

## Списки

Секции маршрутизируют трафик по спискам доменов и подсетей. Подробнее о видах списков — в [sections.md](sections.md#списки).

- **`.srs` и `.json` по URL** (community-списки и удалённые списки в этих форматах) Okop скачивает сам и хранит в `/etc/okop/rulesets` (настройка `ruleset_cache_path`). sing-box читает их как локальные файлы.
  - Пока списка ещё нет (первая установка, GitHub недоступен), вместо него используется пустой. sing-box запускается в любом случае.
  - Когда список скачан, sing-box подхватывает его сам, без перезапуска.
  - Файл заменяется, только если содержимое изменилось, поэтому на флеш пишется редко.
  - Повреждённый файл (например, после пропадания питания) заменяется пустым до следующего скачивания.
- **Текстовые списки по URL** и **списки подсетей community-сервисов** тоже хранятся на флеше, в `/etc/okop/rulesets/lists`. При старте Okop сразу применяет сохранённые копии, без доступа к сети, а при неудачном обновлении остаётся предыдущая копия.
- **Пользовательские и локальные списки** собираются при каждом старте из настроек и файлов на роутере.

Списки обновляются при старте Okop и по расписанию (настройка `update_interval`, задача в cron). Если при старте сеть ещё недоступна (WAN или прокси поднимаются позже), обновление повторяется с паузой от минуты до получаса, пока не получится. Одновременно идёт только одно обновление. Если включено «Скачивать списки через подключение», загрузка идёт через выбранное подключение. Напрямую — только если это разрешено отдельной настройкой, см. [settings.md](settings.md#списки).

Обновить списки вручную можно кнопкой **Обновить списки** на вкладке **Диагностика**. Пока обновление идёт, кнопка недоступна, а по его окончании появляется уведомление: списки обновлены, какие списки не скачались или почему обновление не началось (не работает DNS, нет доступа к GitHub). Если обновление уже идёт, например по расписанию, кнопка дожидается его, а не запускает второе. Перезапускать Okop после обновления не нужно.

Результат последнего обновления — по кнопке, по расписанию или при старте — показан на дашборде, строка **Списки** в блоке «Информация о сервисах»: «✔ Обновлены в 04:00» или «⚠ Не скачались: 2» с именами списков. Списки, которые не скачались, продолжают работать в прошлой версии.

## Защита DNS

Если sing-box не отвечает, а dnsmasq продолжает отправлять ему запросы, в сети перестают открываться вообще все сайты. Чтобы этого не случалось, Okop следит за DNS:

- В фоне раз в 5 секунд он проверяет две вещи: отвечает ли sing-box вообще и может ли он ещё резолвить домены через свой DNS-сервер.
  - Первая проверка использует служебный домен `fakeip.podkop.fyi`: sing-box отвечает на него сам, интернет для этого не нужен. Она показывает, что процесс жив.
  - Вторая проверка запрашивает `openwrt.org` — домен не из списков, поэтому sing-box обязан переслать запрос на DNS-сервер из настроек. Без неё самый частый сбой остаётся незамеченным: sing-box жив и отвечает, но его DNS-сервер недоступен (например, заблокирован провайдером), и в сети не открывается ничего, кроме доменов из списков.
- Пока обе проверки проходят, dnsmasq отправляет запросы в sing-box.
- После трёх неудачных проверок жизни подряд (около 15 секунд) или шести неудачных проверок резолвинга (около 30 секунд) dnsmasq возвращается на обычные DNS-серверы. Маршрутизация по доменам на это время не работает, зато интернет в сети есть. Порог для резолвинга выше, чтобы медленный или временно капризный DNS-сервер не переключал dnsmasq туда-обратно.
- Если sing-box не отвечает совсем, Okop заодно перестаёт отправлять ему трафик к подсетям из списков (Telegram, Discord, свои подсети): пока sing-box лежит, такие соединения идут напрямую, а не в никуда.
- Когда sing-box снова отвечает три проверки подряд (и резолвит), всё переключается обратно. Несколько проверок нужны, потому что падающий sing-box procd перезапускает, и между падениями он успевает ненадолго ответить.

С включённой опцией «Не трогать мой DHCP!» Okop не трогает dnsmasq, но трафик к подсетям при падении sing-box всё так же пускает напрямую.

Если dnsmasq остаётся на обычных DNS-серверах, причину стоит искать в настройке **DNS-сервер**: Okop пишет в системный журнал, что sing-box не смог разрешить проверочный домен.

Что защита делает сейчас, видно на дашборде, в блоке «Информация о сервисах», строка **Защита DNS**. Строка обновляется раз в 15 секунд:

| Строка | Что происходит |
|---|---|
| ✔ Работает | DNS и трафик к спискам идут через sing-box |
| ⚠ sing-box не отвечает с 19:30 | DNS и трафик к подсетям из списков идут напрямую |
| ⚠ DNS-сервер sing-box недоступен с 19:30 | DNS идёт через обычные серверы, домены из списков не маршрутизируются |
| ✘ Не запущена | Okop остановлен |

Время — момент переключения. То же самое в JSON выдаёт команда `okop get_dns_guard_status`.

При переключении Okop меняет только то, что необходимо:

- Перенаправления для отдельных доменов в поле «DNS forwardings» (`/corp.lan/10.0.0.53`) продолжают работать.
- Общие upstream-серверы на время работы Okop сохраняются в опциях `okop_*` секции dnsmasq и затем возвращаются в исходном порядке. Настройки, добавленные в dnsmasq, пока Okop работал, при этом сохраняются.

Если включить «Не трогать мой DHCP!» (`dont_touch_dhcp`), Okop не переключает dnsmasq на sing-box, и защита DNS не работает: направить DNS в sing-box нужно самостоятельно. Если опцию включить, когда Okop уже работает, он всё равно вернёт настройки dnsmasq, которые сохранил при переключении, — иначе сеть осталась бы без DNS.

## Файлы и процессы

| Что | Где |
|---|---|
| Настройки | `/etc/config/okop` |
| Скрипт и библиотеки | `/usr/bin/okop`, `/usr/lib/okop/` |
| Конфигурация sing-box | `/etc/sing-box/config.json` (настройка `config_path`) |
| Кэш sing-box (fake-IP) | `/tmp/sing-box/cache.db` (настройка `cache_path`) |
| Скачанные списки | `/etc/okop/rulesets/` (настройка `ruleset_cache_path`) |
| Временные списки | `/tmp/sing-box/rulesets/` |
| Таблица nftables | `inet OkopTable` |
| Таблица маршрутизации | `105 okop` в `/etc/iproute2/rt_tables` |
| Обновление списков | задача `okop list_update` в cron, результат последнего в `/var/run/okop_list_update.status` |
| Логи | `logread -e okop`, `logread -e sing-box` |

sing-box запускается как отдельный сервис `sing-box`. Его автозапуск Okop отключает, потому что стартует его сам.
