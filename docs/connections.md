# Подключения

Подключение — это то, через что секции отправляют трафик: прокси-сервер, VPN-интерфейс или группа из нескольких подключений. Подключения настраиваются на вкладке **Службы → Okop → Подключения**, а секции на вкладке **Секции** только выбирают, через какое подключение идёт их трафик (см. [sections.md](sections.md)).

Одно подключение может обслуживать несколько секций. Например, YouTube и Discord в разных секциях со своими списками, но через один и тот же сервер.

В таблице подключений для каждого видно тип, сервер или интерфейс (без паролей и ключей) и столбец **Где используется**: секции, группы и скачивание списков. Подключение, которое где-то используется, удалить нельзя: сначала выберите там другое. Имя нового подключения может содержать латинские буквы, цифры и `_` и не должно совпадать с именем секции.

## Типы

| Тип | Что это |
|---|---|
| **Ссылка на прокси** | Одна ссылка: `vless://`, `ss://`, `trojan://`, `socks4://`, `socks5://`, `hy2://` или `hysteria2://` |
| **JSON для sing-box** | Готовый outbound sing-box в формате JSON, для того, что не выражается ссылкой |
| **Сетевой интерфейс** | Интерфейс туннеля роутера: WireGuard, AmneziaWG, OpenVPN и т. п. |
| **Группа: резерв** | Первое отвечающее подключение из списка, по приоритету |
| **Группа: самое быстрое** | Подключение с наименьшей задержкой (URLTest) |
| **Группа: ручной выбор** | Подключение, выбранное на дашборде (Selector) |

### Ссылка на прокси

Примеры поддерживаемых вариантов (транспорты, Reality, obfuscation) — в [String-example.md](../String-example.md). **UDP over TCP** передаёт UDP внутри TCP-соединения; работает для SOCKS и Shadowsocks, если сервер это поддерживает.

### Сетевой интерфейс

- **Сетевой интерфейс** — интерфейс туннеля, например `wg0` или `awg0`. Сам туннель настраивается средствами OpenWrt (см. [tunnels.md](tunnels.md)), Okop только направляет в него трафик.
- **Domain Resolver** — резолвить домены, которые идут через это подключение, отдельным DNS-сервером, запросы к которому тоже идут через туннель. Полезно, если сервис отдаёт разные адреса в зависимости от страны.

Если интерфейс туннеля пропал (туннель упал или ещё не поднялся), sing-box продолжит работать: перестанет открываться только трафик через это подключение. Чтобы в это время трафик шёл через другое подключение, объедините их в группу-резерв.

## Группы

Группа объединяет другие подключения, поле **Участники**. Участником может быть любое подключение, в том числе другая группа; группа не может содержать саму себя, в том числе через другие группы.

### Резерв

Используется первый участник списка, пока он отвечает. Порядок участников — это приоритет.

- Okop проверяет участников запросом к **URL для проверки** с интервалом **Интервал проверки** (по умолчанию каждые 15 секунд).
- Если текущий участник не ответил на две проверки подряд, трафик переходит на следующего отвечающего.
- Когда участник с более высоким приоритетом снова отвечает три проверки подряд, трафик возвращается на него. Несколько проверок нужны, чтобы не прыгать туда-обратно, пока сервер или туннель только поднимается.
- При переключении открытые соединения закрываются: иначе они висели бы на подключении, которое не отвечает. Звонок или загрузка в этот момент прервётся.
- Если не отвечает никто, трафик остаётся на текущем участнике.

Пример: VPN-интерфейс `wg0` как основной канал и VLESS-сервер как запасной. Создайте подключение-интерфейс, подключение-ссылку и группу-резерв с участниками в порядке «интерфейс, ссылка», а в секции выберите группу.

Учтите, что основной и запасной каналы почти наверняка выходят в интернет с разных IP. Сервисы, которые привязывают сессию к адресу или стране, могут попросить войти заново.

На дашборде группа-резерв показывает, какой участник сейчас используется. Выбрать его вручную нельзя: Okop переключает группу сам. Переключения видны в журнале:

```
logread -e okop | grep "Connection '"
```

### Самое быстрое

sing-box сам выбирает участника с наименьшей задержкой.

- **Интервал проверки** — как часто проверять участников (по умолчанию каждые 3 минуты).
- **URLTest Tolerance** — на сколько миллисекунд новый участник должен быть быстрее текущего, чтобы на него переключиться (50–1000, по умолчанию 50).
- **URL для проверки** — адрес для проверки (по умолчанию `https://www.gstatic.com/generate_204`).

Автоматический выбор можно переопределить на дашборде.

### Ручной выбор

Используется первый участник, другой выбирается на дашборде.

## Смешанный прокси

**Включить смешанный прокси** и **Порт смешанного прокси** поднимают на LAN-адресе роутера HTTP/SOCKS5-прокси. Всё, что в него приходит, идёт через это подключение. Удобно для отдельных программ или для проверки подключения. Порты 22, 53, 80, 443 и 9090 заняты самим роутером, и у двух подключений не может быть один порт.

## Переход с Okop 0.6 и раньше

Раньше подключение было частью секции: секция Proxy хранила ссылку, JSON или список ссылок для Selector/URLTest, секция VPN — интерфейс. При обновлении Okop переносит каждое такое подключение на вкладку **Подключения**, и секция начинает на него ссылаться:

- секция `main` со ссылкой или JSON → подключение `main_out`;
- секция Selector или URLTest → группа `<секция>_out` и по подключению на каждую ссылку: `<секция>_1`, `<секция>_2`, …;
- секция VPN → подключение-интерфейс `<секция>_out` вместе с настройками Domain Resolver;
- смешанный прокси и выбор секции для скачивания списков переходят на подключение.

Конфиг в старом формате, восстановленный из резервной копии, Okop преобразует так же при следующем запуске.
